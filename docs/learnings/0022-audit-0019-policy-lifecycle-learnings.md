# 0022 — audit of 0019, part 3: the policy lifecycle — Learnings

## Summary
- **Findings:** 16 items, no high-severity defect. Fixed: 4 medium (the unmet-algorithm warning skipped every route naming no floor or ban; concurrent activations recorded the wrong `before` and could record a no-op; concurrent identical uploads minted duplicates and lost version races; a cache hint on a `source_cidrs` rule is reused from any address and nothing warned), 8 low (a ban was a typo warning when no build had declared its offer; an out-of-range validator severity read as advice; replay zeroed unreadable values; five partial explain stories; dry-run cases that asked another question; a phantom diff line; policyctl split records on a line break; `simulate` asking nothing exited 1), 14 test gaps a mutation passed, 9 doc errors. Full table and every mutation in Details.
- **Fixed, by commit:** `cb8b425` the publish-time report (unmet for every route, typo judged only against declared offers, `authoring.cache_hint_spans_sources`, severity outside the enum is an outage, id and negative-case tests); `8f723cc` per-tenant policy lock, upload by digest, `algorithm.policy_unmet_truncated`; `c88d833` replay lists what it cannot read and reads only a `RecordWindow`, explain refuses five more shapes; `cb0dcd8` dry-run refusals, the diff's phantom line and dead bound, policyctl's TSV and usage exits; `7dfb3b4` `ext/policy.go`, PLAN §5.6/§3, `v0.9.0`.
- **Severity model (item 1): confirmed, no proposal.** Accept-by-id is the override, not a refusal: the same caller lifts it in the same call, the 409 lists each id, and the record names it. M17's fail-safe holds once a typo check no longer warns from absence of proof (`cb8b425`). Control's checks never block (now a test).
- **Confirmed as built:** items 1, 2, 4. **Confirmed after the fixes:** 3, 5–16.
- **Open:** none. **Asked of the user in the PR:** whether the new source-network cache warning (item 5) stays a fix or goes back to a proposal; it gates activations that passed under `v0.8.0`.
- **0019 claims this corrects:** explain "total by construction"; replay "a record whose inputs do not decode is listed" (others were silently zeroed); "a stored `target.algorithm_policy_unmet` under the route's profile" (floor/ban routes only); "a ban no recorded build offers" (also when none declared); "13" codes (15 now); the id "names what the finding is about (proxy, target…)" (list findings are per rule); `ext.PolicyValidator`'s "the compiler's own checks are the whole of validation"; v0.6.0 and control#69 omitted when a validator runs and what `AuthorID`/`ProposedAt`/`ActiveVersion` hold.
- **Decisions:** none added, amended or withdrawn; register unchanged. **Migrations:** none. Release `v0.9.0`, `### Breaking` (behaviour only). **Cross-repo:** a downstream sync for `hoplock/enterprise` (see PR); none for `hoplock/proxy`.

## Details

### How the audit was run

Every item was read in the code as it is on `main` after `960b19e` (part 2
merged), with `git diff 7e3d002 1b9bf55` only to find what 0019 touched.
"Mutation" means: change the rule, run the package's tests, record what
fails, revert (a helper applied one replacement, ran the tests, and restored
the file). A mutation nothing caught is a test gap; each got a test that fails
under it. Six were also run against the pre-0022 suite in a worktree at
`960b19e`, and all six passed it (marked † below).

Environment notes: as 0021's (`service postgresql start`, the password, and
golangci-lint v2.14.0 built with `GOTOOLCHAIN=go1.27.0`). The DB tests need
`HOPLOCK_TEST_DSN` exported in the same shell; without it they skip and a
package "passes" in milliseconds.

### Observations, not defects

- **List findings accept the list as it stands at activation.** `no_proxy_provides`, `target_cannot_take`, `target_unproven`, `target_below_floor` and `target_not_reported` are one id per rule, so an acceptance carried forward covers a proxy or target that joins the list later. That is what lets CI's `-accept` lines survive fleet churn; an id per target would break them on every new host. The report recomputes at activation, so the finding still shows the current list.
- **Ids are joined with `/` unescaped.** A rule id may contain `/`, so two crafted ids could collide (rule `a/b` with executable `c` against rule `a` with executable `b/c`). Both rules are the same author's, in one bundle; not worth changing an id format CI already carries.
- **Activating the active version still recomputes the report**, and refuses a new unaccepted warning rather than answering "unchanged". Nothing is written either way.
- **A validator's `AuthorID` is empty for every CI apply**, because a token is no subject. A "second author" rule cannot be written against it; that is Enterprise's to raise if it needs the principal.
- **`seed` writes bundles without the policy lock.** It is the database-direct bootstrap (0019, 0021); racing it with an upload is a conflict error, not a duplicate.
