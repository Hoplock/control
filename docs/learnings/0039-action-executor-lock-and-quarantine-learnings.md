# 0039 — inbound actions, a subject lock and a target quarantine — Learnings

## Summary
- **M28** (new; completes M15's *disabled* form for the action point): a lock and a quarantine are standing denials applied above the engine, and an inbound action pulls only levers an operator can. Release `v0.26.0`, MINOR; migration `0020` (`subject_locks`, `target_quarantines`, `action_executions`). No `ext` signature changed. Answers `Hoplock/enterprise#26`.
- **Kinds, selectors, `Affected`** (a kind takes exactly its selector; another is `KindInvalid` naming the field). `kill_session`: exactly one of `SessionID` / `SubjectID`; `Affected` 1 = the kill Control published (never sessions seen to close). `lock_subject`, `unlock_subject`: `SubjectID`. `revoke_grant`: `GrantID`. `quarantine_target`: `TargetID`. Lock, unlock, quarantine, revoke: 1 when this call changed it. Zero with a nil error is nothing to act on, with `ReasonCode` `already_locked` · `not_locked` · `already_quarantined` · `already_revoked` · `expired`. Lifting a quarantine is an operator's only; a lock's expiry is Enterprise's (execute `unlock_subject`).
- **Errors.** `KindInvalid` (names the field; do not retry unchanged) · `KindNotFound` (unknown subject, session, grant or target in `Action.Tenant`, which includes another tenant's) · `KindDenied` + `ReasonCode` `break_glass_subject` (a lock on a break-glass subject; an operator's still works; a retry gets the same) · `KindConflict` (id reused for a different action) · `KindUnavailable` (**safe to retry under the same `ActionID`**: the act was made and stands, the stream refused the publication or Control is stopping) · `KindInternal` (store failure).
- **`ReasonText`**: shown to the holder verbatim, so one line, no control characters, ≤ 512 bytes, else `KindInvalid` on `reason_text`, never truncated or replaced. Empty → Control's words, verbatim: kill `Your session was ended as part of a security response.` · lock `Your access was suspended as part of a security response.` · grant `Your temporary access grant was revoked as part of a security response.` (an operator's lock with no reason: `Your access has been suspended by an administrator.`). `ReasonCode`: one line ≤ 128 bytes; `ExternalRef` ≤ 256.
- **Idempotent per tenant on `ActionID`**: same action → first result, no second record, the kill sent again (a lock or quarantine only while it still stands); a retry with other words is still the same action (kind + selector decide).
- **Routes**, all under `session:revoke` (`grant-admin`, `admin`): `POST …/subjects/{subject}/lock` · `unlock`, `POST …/targets/{target}/quarantine` · `release`, body optional `reason_code`, `reason`; each `200` says whether it changed anything (`placed` / `unlocked` / `released`); `503 standing_denial_undelivered` = in force, ask again; `DELETE` of a quarantined target `409 target_quarantined`. `GET` subjects and targets carry `locked`/`lock`, `quarantined`/`quarantine`; a deleted-while-locked subject reads `record_missing`.
- **Records**, all on the control stream: `operator.subject.locked` · `unlocked`, `operator.target.quarantined` · `released`, `grant.revoked`, `operator.revocation.published` (a kill, written once it is published), plus `action.unchanged` and `action.refused` for an action. Each carries `action_id`, `action_kind`, `external_ref`, `reason_code`, `provider`. **Actor `action-handler:<provider>`, no subject**, on records and grant rows.
- **Handler lifecycle**: `Start(ctx, exec)` once, after the registry is sealed, before either listener opens; `Stop` before they drain, bounded by the shutdown grace. A `Start` that errors, panics or exceeds 30 s is logged `ERROR` (`action_handler_not_started`, `provider`, `kind`), Control serves, and `GET …/extensions` shows the row `started: false`, `start_error: <kind>`. An unreachable platform is not an error: return nil, reconnect on your goroutines.
- **Key files**: `internal/standing/`, `internal/action/{executor,runner}.go`, `internal/decision/{inputs,record,explain,replay,service}.go`, `internal/store/{standing,targets}.go`, `internal/access/revoke.go` (`RevokeWithin`, `Finish`, `Resend`), `internal/httpapi/north/standing.go`, `internal/daemon/action.go`.
- **Gotchas**: a standing denial skips the grants read, the probes and the compiled policy, so the record has `basis: standing` and no rule; the decision path sends the same four statements as before (`TestStandingDenialsCostTheDecisionPathNoRoundTrip` counts them). `action_executions` is never swept.
- **NEXT (0040)**: a deactivation is a second nullable join in `Subjects().Standing` and a second `standingDenial` in `internal/decision/inputs.go`, not a second query. Enterprise's sync is queued (see the PR).

## Details

### Decisions made, and the places this phase read the prompt
- **M28 is new.** The register row, §3, §5.3, §6, §7 and §10 are revised in place; M15's *disabled* sentence now notes it is true for every kind.
- **A no-op is recorded as `action.unchanged`, not as the lever's event.** The prompt says an execution that "found nothing to act on writes the record the operator's lever writes". For a lock already standing that would be a second `operator.subject.locked`, and for a grant already revoked it would be a `grant.revoked` naming the handler as revoker of a grant somebody else revoked — false rows in the two queries an auditor runs ("who locked this", "who revoked this"). Every execution is still audited, which is what the request asked, under an event that does not claim an act.
- **`kill_session` for a session this tenant has no decision for is `KindNotFound`.** The prompt lists subject, grant and target; a typo'd session id answered `Affected: 1` would be a nil error over something that did nothing. The check is `Decisions().SessionExists`, an index-only read. A kill by subject needs a subject row or a lock on the id.
- **Unlock of a subject with no lock** is `Affected: 0, not_locked` if Control has a row for the subject and `KindNotFound` if it has neither, so the lock of a deleted subject can still be lifted and an unknown id is not "not locked".
- **A lock or quarantine already standing still publishes** (a `200`, no record). A publication that failed is only repaired by asking again, and refusing to send it would leave a lock whose kill was never delivered with no way to deliver it. A repeat of an `ActionID` re-sends only while the lock or quarantine still stands, so a late duplicate cannot end the sessions of a subject who was unlocked since. A repeated kill by subject does re-send, as the prompt specifies, with that consequence.
- **A placed denial publishes twice**, the second pass after one decision budget (`cfg.Decision.Budget` + 500 ms), as a grant's revocation does. The route and the executor block for it; a repeat does not.
- **A quarantine invalidates `all` for the tenant**, not keys. The record that carries a cache key is not indexed by target, and indexing the table the decision path writes on every call for a rare emergency act costs M5 more than the act saves. The prompt allowed `all`.
- **`ReasonCode` is validated as one bounded line, not as a stable-code pattern**, because the prompt says bounded single lines and a SOAR vendor spells its own. It is `access.NormalizeReasonCodeLine`; grants keep their pattern.
- **The `Start` timeout (30 s) is mine.** The prompt says a `Start` error is a broken registration; a `Start` that never returns is the same fault, and waiting for it would make Control's start-up depend on somebody else's automation. If it returns late, its answer is the truth.
- **`action.refused` for an empty tenant** is recorded in the deployment's configured tenant (`Options.DefaultTenant`), since an empty tenant has no stream. What a refused action sent is recorded only where it is fit to be: an id with a control character in it is blanked.
- **The kill's record is written after the publication**, under the action's lock, and a column (`action_executions.recorded_at`) says whether it has been. A retry after the stream refused the first publication is how the record the first execution owed gets written, and it is written once.
- **`store.WithQueryTracer` and `storetest.NewWith`** were added so a test can count statements. They are not a logging hook.

### How to extend
- A new standing denial on a subject or target: a table of its own with no foreign key, a nullable join in `Subjects().Standing` or `Targets().StandingByHostname`, a `standingDenial` in `internal/decision/inputs.go` (its code is stable), and an entry in `recordedStanding`. The decision, record, explain and replay need no other change.
- A new `ActionKind` is an `ext` change and a new `apply` case in `internal/action/executor.go`, through the service an operator's route calls.

### Follow-ups and known gaps
- **`action_executions` grows without a bound.** A row deleted early is an action id that can be executed twice, so the retention is a decision for the first deployment to make with its own volumes in front of it.
- **Enterprise's half** (its 0007, E7) is its own: the inbound transport, credentials, scopes, the blast-radius cap, the lockout lifecycle's expiry.
- **The console (0044)** and **the E2E topology (0045)** were amended in this PR to show and offer a lock and a quarantine, and to run one scenario in which a handler kills a session and locks its subject.
- **Cross-repo:** a downstream sync for `hoplock/enterprise` is queued in `prompts/downstream/queued/`; `hoplock/proxy`: none, the contract is untouched (M1).
